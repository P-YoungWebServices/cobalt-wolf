Playback engine

Cobalt Wolf's player is built on Media3/ExoPlayer with an FFmpeg decoder extension. Instead of a fixed device profile, it detects what your hardware can do every time you press play and picks the highest-quality path that will actually work.

How a playback path is chosen

On every playback start, the app probes:

  • Decoders — which codecs and profiles the device can decode in hardware (H.264, HEVC, AV1, VP9) and up to what resolution/level.
  • Display — whether the connected panel supports HDR10, HDR10+, HLG or Dolby Vision.
  • Audio output — which encoded formats the HDMI sink (TV/receiver/soundbar) reports for passthrough.

It then walks the fallback order below and stops at the first level the file and device both support.

The fallback order

LevelWhat happens
1. Direct playThe file is streamed as-is and decoded by the device's hardware decoders. Zero server CPU. Used whenever the codec, resolution, HDR format and audio are all supported.
2. Local FFmpeg decodeThe stream is still direct-played, but the bundled FFmpeg decoders handle formats the hardware can't. Costs device battery/CPU; needs no server transcoding.
3. Server transcodeThe last resort: Jellyfin transcodes to a supported format. Honors a configurable codec preference and codec-level caps.

A decoder that fails mid-playback drops down the same chain automatically and resumes where it stopped — you see a blip, not an error screen.

Video & HDR

  • Codecs: H.264, HEVC, AV1, VP9 — up to the device's decoder limits (4K where the hardware allows).
  • HDR: HDR10, HDR10+, HLG and Dolby Vision profiles 5, 7 and 8, when both the decoder and the display support the format.
  • Graceful degradation: unsupported Dolby Vision plays its HDR10/HLG/SDR base layer; HDR10+ plays as HDR10; HDR on an SDR display is tone-mapped by the server transcode.
  • Display matching (TV): the output frame rate switches to match the content (23.976, 24, 25, 30, 50, 60 Hz…), and HDR is only signalled while HDR content is actually playing — your TV won't be stuck in HDR mode for SDR video.

Audio

  • Passthrough when the HDMI sink reports the format: Dolby Digital, Digital Plus (incl. Atmos), TrueHD (incl. Atmos), DTS, DTS-HD MA (incl. DTS:X).
  • PCM decode on-device when passthrough isn't available — your receiver still gets multichannel, just decoded on the player.
  • Night mode — loudness normalization for late-night listening.
  • Track picker — switch audio tracks during playback, or pick a different media source/version before starting.

Subtitles

  • ASS/SSA — full styling via bundled libass (fonts, positioning, karaoke, transforms).
  • PGS — image-based subtitles rendered in the player.
  • SRT / external text — rendered natively with a per-track delay offset control to fix out-of-sync subs.

Player controls

  • Gestures (touch): swipe for brightness and volume, drag to seek.
  • Trickplay — seek thumbnails while scrubbing, when the server provides them.
  • Extras: playback speed, repeat modes, chapter navigation, "Ends at" wall-clock.
  • Intro/outro skip — Jellyfin MediaSegments are shown as a skip button; on TV it's auto-focused.
  • Next episode — a real next button once the next item resolves, plus auto-advance when an episode ends (disabled inside SyncPlay groups).
  • Picture-in-picture on phones and tablets.

The stats overlay

Enable the stats overlay for a live readout, updated continuously:

stats · codec hevc · decoder c2.*.hevc.*
hdr HDR10 · audio TrueHD → passthrough (Atmos)
out 3840×2160 @ 23.976 · dropped 0

It shows the active codec, the decoder in use, HDR type, whether audio is passthrough or PCM, sample rate, channel layout, output resolution/frame rate and dropped frames — the first thing to check when diagnosing playback issues.

Playback settings & overrides

The Playback settings page lists exactly what capability detection found on your device — decoders, HDR formats, audio outputs — and lets you override the automatic choices:

  • Decoding: Auto · Prefer local decode · Always transcode
  • Audio output: Auto · PCM only
  • HDR: Auto · SDR only
  • Dolby Vision: on/off
  • Styled subtitles: ASS/SSA rendering on/off
Overriding to Always transcode or PCM only is the fastest workaround for a device with a flaky decoder or an audio receiver that misreports its formats.

Matroska seeking

Some ffmpeg-remuxed MKVs only reference their seek index (Cues) from a second SeekHead at the end of the file, which ExoPlayer's Matroska extractor never follows — making the file report itself as unseekable. Cobalt Wolf probes the MKV over HTTP range requests before playback, builds the cue index itself and injects a real seek map, so scrubbing, rewind/fast-forward and seekTo all work on those files.
