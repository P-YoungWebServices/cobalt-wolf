Troubleshooting

Work through the relevant section. Most playback problems come down to a device capability being misdetected or a receiver misreporting its formats — both have overrides.

Connecting & signing in

  • "Can't reach server" — verify the URL scheme and port (http://server:8096 is the default), and that the device is on the same network. Try the address in a browser first.
  • Server too old — Cobalt Wolf requires Jellyfin 12.0+. Check your server version under Dashboard → General.
  • Quick Connect fails — it must be enabled on the server (Dashboard → General → Quick Connect), and the approving client must be signed in to the same account.
  • Kicked back to sign-in — the server invalidated your token (restart, plugin update, token revoked). The profile is removed; sign in again.
  • Admin features missing — they're gated by your Jellyfin user policy's administrator flag, not an app setting. See Admin dashboard.

Playback

  • Enable the stats overlay first — it shows which decoder, HDR path and audio output are actually in use. Most mysteries end there. See Playback engine.
  • Stuttering on high-bitrate files — the device may be software-decoding. Check the stats line; if the decoder is FFmpeg-based, the hardware can't handle that codec. Let the server transcode (Playback settings → Always transcode) or get a lower-bitrate version.
  • Video looks washed out / wrong colours — an HDR/SDR mismatch. Set Playback settings → HDR to SDR only to force tone-mapped output.
  • Dolby Vision looks like HDR10 — that's the intended fallback: profile 7/8 content plays its HDR10 base layer when the display can't do DV. Check the Playback settings page for what was detected.
  • No audio on passthrough — the receiver/soundbar reported a format it doesn't actually handle. Set Audio output to PCM only.
  • Audio out of sync on a specific file — try a different audio track or media version; if only that file is affected it's likely the encode, not the player.
  • Can't seek in an MKV — update to the latest release; files whose seek index only lives at the end of the file are handled by the built-in cue probing. If it still fails, remux the file (ffmpeg -i in.mkv -c copy out.mkv).

Subtitles

  • Styling looks wrong on ASS subs — toggle styled subtitles off/on in Playback settings; a very rare libass edge case may render better as plain text.
  • Subs out of sync — use the per-track delay offset on external text subtitles.
  • No subtitles listed — check the track picker during playback; also confirm the file actually has subtitle streams (detail page → media info).

TV-specific

  • Phone UI on a TV — the device doesn't report itself as a television to Android. This is a device quirk; report it with the model name.
  • Keyboard pops up unexpectedly — shouldn't happen: TV text fields stay read-only until focused and confirmed. If it does, report which screen.
  • No home-screen channels — expected on Fire TV (no TV provider). On Android TV/Google TV, add the channel from the launcher's channel customization.
  • Judder on 24p content — frame-rate matching needs the TV to allow display mode changes. Check the display stats line shows the content's rate.

Services (Seerr, *arr, qBittorrent)

  • Service shows offline — test the URL in a browser from the same device; check the API key is current (arr apps regenerate them).
  • qBittorrent keeps logging out — the app re-logs in automatically when the cookie expires; persistent failures mean the WebUI credentials changed.
  • Seerr sign-in rejected — sign in with your Jellyfin credentials, not a separate Seerr password.

Still stuck?

Open an issue and include:

  • Device model, Android version, Jellyfin server version
  • The stats overlay output for playback problems
  • What you expected vs. what happened, and the steps to reproduce
